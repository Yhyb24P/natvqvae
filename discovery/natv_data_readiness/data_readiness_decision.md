# NatV 本地数据可用性核查

## 判断

现有正式训练与验证序列可用于下一步生成任务设计；旧掩码任务的表示和演化特征可按原任务复用。实际文件、角色、派生输入与 SHA256 见 `data_checks.json`。输入含义和使用入口见 `../../docs/DATA_PROVENANCE.md`。

| 对象 | 核查结果 |
|---|---|
| 来源输入 | 当前清单 15 项均存在，SHA256 一致；角色表、划分与旧运行记录相符 |
| 发现群体 | 2,430 条不同序列，FASTA 与角色表逐条相同，ID 等于序列 SHA256，长度元数据一致 |
| 正式训练 | 1,644 条、47 个组分，长度 270–411 aa |
| 验证 / 测试 / 旧封存 | 227 / 231 / 75 条；与训练组分两两不重叠 |
| 注释冲突隔离 / 排除 | 249 / 4 条；不进入训练或验证导出 |
| 既有检索群体 | FASTA 与查询计划均恰好包含正式训练的 1,644 条 |
| 历史查询 | 13,097 条；训练 11,508、验证 1,589，每条允许使用的序列对应 7 个掩码方案 |
| 掩码表示 | 13,097 个文件，约 24.9 GB；逐文件校验、读取、身份、维度、有限数值、目标位点与实际 mask token 核查 |
| 演化特征 | 13,097 个文件，约 34 MB；逐文件校验、读取、长度×21 维度、有限数值，且与表示文件内的演化特征逐元素一致 |
| 结构注释 | 已有结构解释文件引用的四张来源表 SHA256 一致；实验结构输入校验通过 |

训练群体最大的五个组分含 440、358、326、271、96 条，共 1,491 条，占训练序列的 90.7%。序列条数不能视为独立演化样本数；模型比较应保留组分身份，并明确抽样与权重。

KVP40 WT、Q5NHR1、Q55928 均属于旧封存组分，不能因为它们是参考序列或实验模板就加入训练或检索。训练和验证序列均只含 20 种标准氨基酸。

## 可直接读取的文件

`training.fasta` 和 `validation.fasta` 按原角色分开导出；检索使用 `training.fasta`。`samples.csv` 包含这两组序列、角色、组分、长度及原 CDD 坐标；`roles.csv` 保留全部群体的角色与组分，不含序列。四份导出文件的校验值保存在 `data_checks.json`。大型特征通过 `inputs/manifest.json` 定位只读来源，未另建一份缓存。

## 适用范围

历史特征按原掩码查询制作，不能据其完整性宣称新的家族全长生成任务已具备输入。训练序列长度不一，不能直接套用 WT 的 341 位点坐标；CDD 坐标属于各自序列。新的生成任务仍需明确 padding、掩码与目标、位置对应、检索及评价信息范围。

本核查验证了特征身份与内容一致性，没有独立重算上游检索或 ESM-2 表示；其来源仍继承旧输入计划。全家族 MSA 不能在未确定成员角色时直接作为训练演化输入。新任务特征的适用性与实验活性标签仍为 UNKNOWN。

## 复现

在项目根目录执行：

```bash
/home/yhshy/miniconda3/envs/nad_data/bin/python discovery/natv_data_readiness/check_data.py
```

脚本依赖 pandas、Parquet 引擎、NumPy 与 PyTorch；本次环境版本、Git revision、脚本及输入校验值见 `data_checks.json`。只读取本地来源并校验约 25 GB 文件；可用 `--root` 指定来源，用 `--out` 输出到其他目录后比较四份导出文件的校验值。
