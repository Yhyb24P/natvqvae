# 执行效率核对

原实现每组八条、每次更新串行检索，ESM2 也执行了不使用的检索；GPU 多数采样时仅 5%–10%。按用户要求中断，原代码、协议身份、逐组产物和状态保留在 `interrupted_slow_run/`，不混入重新运行的分母。

`check_batching.py` 使用中断运行的真实上下文，对比八条与 64 条批处理。共同八条的检索特征逐位相等、检索记录相等；处理吞吐约提高 3.42 倍。SE 遮蔽位置 logits 最大绝对差 0.03125、均值 0.001318，属于本次 bfloat16 批处理观测差异；重新运行完整 2,976 次，不承诺逐条输出与原实现相同。峰值 GPU 分配约 8.52 GB。原始数字见 `batching_check/results.json`。

本次保持编辑任务、种子、位点、尝试数与评价规则。按同方法、同训练种子、同长度批量执行，ESM2 跳过无用检索；分别记录累计检索与编码耗时。训练家族、checkpoint 和只读来源保持原身份。
